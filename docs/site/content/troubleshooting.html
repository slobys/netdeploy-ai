Windows 本地页面打不开

  1. 确认运行 NetDeploy 的 PowerShell 窗口还在，没有按 Ctrl+C。
  2. 打开 http://127.0.0.1:8787/api/health 检查后台版本。
  3. 若提示 8787 端口被占用，先停止旧实例，不要强行同时启动两个服务；之后按 Ctrl+F5 刷新网页。

SSH 连接被拒绝 / 超时

从 Windows PowerShell 检查：

Test-NetConnection YOUR_VPS_IP -Port 22

连接失败说明可能是云防火墙、VPS UFW、sshd 没监听、实例停机或地址/端口错误。连接成功但认证失败，才检查用户名、密码或 SSH 私钥。Google Cloud 用户先从云控制台的浏览器 SSH 入口排查。

SSH 指纹变化、信任失败

VPS 重装、系统更新了主机密钥、IP 发生回收都可能导致指纹变化。请从服务商独立控制台核对后使用 NetDeploy 的 SSH 安全 → 更新指纹；不要使用 StrictHostKeyChecking=no 绕过身份校验。

root 密码正确但仍无法登录

需要区分 root 本地密码、SSH 是否启用密码认证、root SSH 是否被禁用，以及 Google Cloud 的 OS Login/IAM 或 PAM 限制。见 谷歌云专题。修改 root 密码本身不等于开放 root SSH。

UFW 放行了，公网仍打不开

确认 VPS 真正监听对应端口、已通过有效 HTTPS / TLS 配置、云安全组的入站规则确实作用于目标实例，以及源 IP 和协议正确。Google Cloud 和 AWS 的 VPC 规则属于另一层网络控制。

3X-UI HTTPS 签证书失败

检查域名是否解析到该 VPS 公网 IP、TCP 80 是否可从公网访问、Certbot 续期服务是否正常，以及 3X-UI 实际监听与证书配置。如果软件已装好但 HTTPS 阶段失败，应使用 继续完成 HTTPS 创建修复计划，不必覆盖现有 3X-UI。

S-UI 安装后从公网打不开

新安装会尝试签发公网 IP/域名证书，只有证书、续期及 HTTPS 验证通过才会让管理 2095/TCP 监听公网。先在查看 S-UI 面板信息确认显示 HTTPS 直连地址；否则证书尚未生效，仍为本机访问。检查 TCP 80 ACME 验证、DNS A、公网 IP、Certbot 版本、云厂商安全组入站 2095/TCP 和有效证书；不要开放明文 HTTP。

如果 S-UI 已安装但 HTTPS 失败，保持原程序和凭据，到 S-UI 面板状态页点击继续完成 HTTPS即可创建四步证书修复任务，不必重新安装。订阅 2096/TCP 仍只监听本机。

计划提示失效或需要刷新

如果服务器重装、SSH 主机密钥更换、证书域名或安装固定脚本发生变化，历史审批不再有效。可返回服务器控制台重新环境检测、刷新方案、再次审核。已有部分安装时先检查真实 VPS 状态，避免重复执行。

如何反馈故障

在 GitHub Issues 留下：NetDeploy 版本、VPS 系统、CPU、执行项目、出错阶段和脱敏的最后一步错误。禁止上传 SSH 密码、Token、证书私钥、管理员初始密码或完整 .env。
