安装计划不等于已经在你的 VPS 上验证成功

NetDeploy v{{version}} 仍是 Alpha；自动安装已通过本地模拟测试，但不同 VPS 镜像、上游网络和防火墙仍可能产生差异。先用测试服务器。

3X-UI · Xray 面板

  1. 在项目中心选择 3X-UI，选择目标 VPS 和面板端口；默认示例端口 24443/TCP，也可以自定义。
  2. 选择「自动申请证书」时：填了 HTTPS 域名按域名签发，否则尝试公网 IPv4 证书（需 TCP 80）。选择「由 NPM 统一 HTTPS」则不申请证书、不使用 TCP 80 做 ACME 验证，面板保持本机 HTTP。
  3. 检查兼容性与固定脚本，审核批准部署。部署成功且证书验收通过后才可作为公网 HTTPS 地址使用。
  4. 已装 3X-UI 时优先点击 查看已安装面板；如果 HTTPS 阶段失败，走 继续完成 HTTPS，不要覆盖重装。

IP 证书有效期可能为约 160 小时，需要保持续期服务有效。公网面板建议开启强密码、双因素认证与云防火墙管理 IP 白名单。

Debian 13 IP 证书安装修复

Debian 13 自带 Certbot 4.0 无法申请 IP 证书。NetDeploy v{{version}} 会在 IP 模式下自动创建独立 Python 虚拟环境、安装 Certbot 5.8.0，并配置专用续期服务 netdeploy-certbot-renew.timer；不会卸载系统旧 Certbot。曾在「步骤 7/9」失败的用户，请更新 NetDeploy 后点击继续完成 HTTPS，仅重试四步证书配置，不要覆盖重装 3X-UI。

S-UI · sing-box 面板

NetDeploy 使用官方固定 v1.6.6 Release 发行包、SHA-256 校验和随机初始账户，不会运行上游的“最新版本安装脚本”。初次启动前将 Web 管理与订阅监听限制在 VPS 127.0.0.1。

新安装默认自动申请证书：有域名则按域名签发，否则为公网 IPv4 申请短期 IP 证书。也可在安装页面选择「由 NPM 统一 HTTPS」，此时只安装本机 HTTP 管理端，不签证书、不执行 Certbot 和 TCP 80 ACME 验证，交由 NPM 管理 SSL。

证书和续期验收成功后，查看 S-UI 面板信息会显示可直接打开的 https://IP或域名:2095/随机路径/。本机 UFW 会精准放行 2095/TCP，云厂商安全组还须为固定管理 IP 开放 2095/TCP。订阅 2096/TCP 永远只在 VPS 本机监听，不需要公网放行。

证书失败时不会开放公网 HTTP

如果 IP/域名证书未签发或 HTTPS 验收失败，已安装的 S-UI 会保持或恢复 127.0.0.1:2095。你可以先用 SSH 隧道访问，并点击继续完成 HTTPS单独重试证书阶段，无需覆盖重新安装。

# 仅用于暂时本机访问（证书失败或主动选择本机模式）：
ssh -N -p 22 -L 2095:127.0.0.1:2095 root@YOUR_VPS_IP

如果服务已存在，NetDeploy 只检查状态，不重复覆盖。初始密码可能已经由管理员修改；若需重新配置 HTTPS，必须先通过可信 SSH 确认服务仍由 NetDeploy 管理且在本机监听。

仅当选择 S-UI 原生 HTTPS 时：IP 证书使用独立 Certbot 5.8.0 与续期定时器，域名证书使用系统 Certbot；还需在云平台允许 ACME TCP 80 验证和管理 IP 白名单的 2095/TCP。选择 NPM 统一 HTTPS 时，以上面板证书步骤及原始管理端口公网放行均不需要。订阅 2096/TCP 始终不开放公网。

3X-UI / S-UI：交给 NPM 统一申请 HTTPS（不单独申请证书）

同一台 VPS 上部署 3X-UI、S-UI、IT-Tools 和 MyIP 时，可以统一用 Nginx Proxy Manager (NPM) 管理域名与 SSL。在 NetDeploy 的 3X-UI 或 S-UI 安装页面，把「面板 HTTPS 处理方式」选成「不申请证书，交给 NPM 反向代理提供 HTTPS」。

这个模式只有 5 步基础安装：面板仅监听 VPS 127.0.0.1 的 HTTP，不调用 Certbot，不为面板签 IP/域名证书，不会检查、占用或自动放行 ACME TCP 80。TCP 80/443 留给 NPM 使用，面板自身端口不应该公网开放。

3X-UIhttp://127.0.0.1:24443（端口可编辑；保留实际随机 Web 路径）Scheme = http，WebSockets Support = 开启
S-UIhttp://127.0.0.1:2095（保留实际 Web 路径）Scheme = http；订阅 2096 仍只监听本机
特别注意 NPM 的 Docker 网络模式

上面的管理服务绑定的是 127.0.0.1，普通 Docker 桥接网络里的 NPM 容器的 127.0.0.1 指向容器自己，不能直接反代宿主机。要使用这些上游地址，需要将 NPM 的 Compose 服务设置为 network_mode: host，同时删除该服务原来的 ports: 映射再重建容器。Linux 的 host 网络容器与宿主机共用网络，可以连接到 127.0.0.1:24443 或 127.0.0.1:2095。但 NPM 的 HTTP 80、HTTPS 443、管理 81 也会成为宿主机端口，必须在云安全组限制 NPM 81 管理入口。

  1. 检查 NPM 已正确监听 80/443、域名 DNS A 指向该 VPS，云平台放行 TCP 80/443 用于 NPM 的证书申请。
  2. 在 NPM 中创建 Proxy Host，每个服务使用独立域名（如 xui.example.com、tools.example.com）。Forward Host 填 127.0.0.1，Forward Port 按上表，Scheme 选 http。3X-UI 还需要开启 WebSockets Support。
  3. 切换到 NPM 的 SSL 标签，由 NPM 申请、续期证书并开启 Force SSL。测试 https://你的域名/实际面板路径，不要直接把面板 HTTP 原始端口开放公网。
  4. 其他 Docker 应用（如 IT-Tools、MyIP）可以通过它们已发布到宿主机的端口作为上游；如果它们只在 Docker 内部网络提供服务，需要按实际容器网络重新配置 NPM 上游。

已有原生 HTTPS 模式不受影响：选择自动申请证书时，3X-UI、S-UI 仍可继续使用现有 IP/域名 Certbot 流程。这个选项只决定新安装如何处理 HTTPS；不会自动安装或修改 NPM，不会覆盖已安装的面板。

sing-box · 只有内核

安装完成代表程序存在，不会自动产生可用代理节点、TLS 证书或公网监听。用户须自行完成合法配置、运行 sing-box check 并检查防火墙策略。

wg-easy · WireGuard

默认 WireGuard 隧道使用 51820/UDP，Web 管理页面绑定 VPS 127.0.0.1:51821。首次访问应使用 SSH 隧道初始化管理员与公网连接参数。

ssh -N -p 22 -L 51821:127.0.0.1:51821 root@YOUR_VPS_IP

Dockge Apps · 自定义端口与 Docker 一键安装

NetDeploy 使用二开仓库 slobys/dockge-apps 的固定提交构建 Docker 镜像，内置 Nginx Proxy Manager、IT-Tools、MyIP 应用中心。

  1. 在 项目中心 → Dockge Apps → 部署项目 中选择 VPS。全新的 Debian/Ubuntu VPS 如果没有 Docker，会自动下载并执行 Docker 官方一键安装脚本，验收 Compose v2、Buildx 与 Git 后继续。
  2. 管理端口留空时自动随机生成 20000–59999；也可以手动填 1024–65535 的端口。会检查与 SSH 和现有服务的冲突；容器内部仍使用 5001。
  3. 新安装默认使用服务器公网 IP + 端口，安装页面不再显示访问方式下拉框；生成方案后，会在执行审批页面明确显示目标地址及高权限、明文 HTTP 和首次管理员设置风险，只有确认审批后才开放端口。
  4. 安装后点击查看 Dockge Apps 面板信息。已有受管理的 Dockge Apps 可以使用修改端口与访问方式，只修改容器端口映射并保留数据，不重新安装。
默认公网直连的安全注意事项

Dockge Apps 访问 Docker Socket，具有很高的 VPS 管理权限。新安装计划默认使用公网 IP + 端口，审批时会再次提醒：首次管理员尚未创建时，其他能访问该端口的人可能抢先注册。建议先在云安全组限制来源为自己的固定管理 IP，或使用 SSH 隧道完成初始化。Docker 映射端口可能绕过 UFW；NetDeploy 不会自行修改云安全组。

# SSH-only 模式示例（实际随机端口以 NetDeploy 显示为准）
ssh -N -p 22 -L 35000:127.0.0.1:35000 root@YOUR_VPS_IP
官方 Docker 脚本

根据你的要求，Docker 安装使用 get.docker.com，不是原先手写的 APT 安装步骤。脚本通过 HTTPS 下载并保存在 VPS 的受保护目录；NetDeploy 会检查语法、dry-run 与文件校验值后执行本地副本。官方建议该便捷脚本主要用于开发与测试，正式服务器请先做好备份。已有 Docker 安装和数据不会自动被覆盖。

项目源码、Compose 配置及数据分别存放在 /opt/netdeploy/dockge/source、/opt/netdeploy/dockge/compose.yaml 和 /opt/netdeploy/dockge/data；/opt/stacks 是 Compose 栈目录，不会自动删除。旧版原生 Dockge 不会被强制替换。

失败、重试与日志

任务列表将显示等待审批、执行中、已完成、部分成功或失败状态。出现异常时，先查看最后一步实际日志，再通过服务器控制台核对远端程序状态。不同版本固定脚本变更后应刷新旧审批方案，不能继续执行过期计划。
