安装计划不等于已经在你的 VPS 上验证成功

NetDeploy v{{version}} 仍是 Alpha；自动安装已通过本地模拟测试，但不同 VPS 镜像、上游网络和防火墙仍可能产生差异。先用测试服务器。

3X-UI · Xray 面板

  1. 在项目中心选择 3X-UI，选择目标 VPS 和面板端口；默认示例端口 24443/TCP，也可以自定义。
  2. 填了 HTTPS 域名则按域名签证书；否则对公网 IPv4 尝试 IP 证书。需要满足公网 TCP 80 可达。
  3. 检查兼容性与固定脚本，审核批准部署。部署成功且证书验收通过后才可作为公网 HTTPS 地址使用。
  4. 已装 3X-UI 时优先点击 查看已安装面板；如果 HTTPS 阶段失败，走 继续完成 HTTPS，不要覆盖重装。

IP 证书有效期可能为约 160 小时，需要保持续期服务有效。公网面板建议开启强密码、双因素认证与云防火墙管理 IP 白名单。

Debian 13 IP 证书安装修复

Debian 13 自带 Certbot 4.0 无法申请 IP 证书。NetDeploy v{{version}} 会在 IP 模式下自动创建独立 Python 虚拟环境、安装 Certbot 5.8.0，并配置专用续期服务 netdeploy-certbot-renew.timer；不会卸载系统旧 Certbot。曾在「步骤 7/9」失败的用户，请更新 NetDeploy 后点击继续完成 HTTPS，仅重试四步证书配置，不要覆盖重装 3X-UI。

S-UI · sing-box 面板

NetDeploy 使用官方固定 v1.6.6 Release 发行包、SHA-256 校验和随机初始账户，不会运行上游的“最新版本安装脚本”。初次启动前将 Web 管理与订阅监听限制在 VPS 127.0.0.1。

新安装默认按服务器信息自动选择证书：填写了域名则验证 DNS A 并签发域名证书；不填域名则为 VPS 公网 IPv4 签发短期 IP 证书。依次完成 S-UI 本机安装、Let’s Encrypt 验证、自动续期、原生 TLS 配置及 HTTPS 验收。

证书和续期验收成功后，查看 S-UI 面板信息会显示可直接打开的 https://IP或域名:2095/随机路径/。本机 UFW 会精准放行 2095/TCP，云厂商安全组还须为固定管理 IP 开放 2095/TCP。订阅 2096/TCP 永远只在 VPS 本机监听，不需要公网放行。

证书失败时不会开放公网 HTTP

如果 IP/域名证书未签发或 HTTPS 验收失败，已安装的 S-UI 会保持或恢复 127.0.0.1:2095。你可以先用 SSH 隧道访问，并点击继续完成 HTTPS单独重试证书阶段，无需覆盖重新安装。

# 仅用于暂时本机访问（证书失败或主动选择本机模式）：
ssh -N -p 22 -L 2095:127.0.0.1:2095 root@YOUR_VPS_IP

如果服务已存在，NetDeploy 只检查状态，不重复覆盖。初始密码可能已经由管理员修改；若需重新配置 HTTPS，必须先通过可信 SSH 确认服务仍由 NetDeploy 管理且在本机监听。

S-UI 的 IP 证书也复用上述独立 Certbot 5.8.0 及专用续期定时器；域名证书保留系统原有 Certbot。请在云服务商面板放行 TCP 80 验证入口，并按管理 IP 白名单设置 TCP 2095。2096/TCP 不需要公网放行。

sing-box · 只有内核

安装完成代表程序存在，不会自动产生可用代理节点、TLS 证书或公网监听。用户须自行完成合法配置、运行 sing-box check 并检查防火墙策略。

wg-easy · WireGuard

默认 WireGuard 隧道使用 51820/UDP，Web 管理页面绑定 VPS 127.0.0.1:51821。首次访问应使用 SSH 隧道初始化管理员与公网连接参数。

ssh -N -p 22 -L 51821:127.0.0.1:51821 root@YOUR_VPS_IP

Dockge Apps · Docker Compose + 一键应用中心

NetDeploy 已把原版 Dockge 的新安装模板替换为二开项目 slobys/dockge-apps（源码版本 1.5.0-apps.1）。内置 Nginx Proxy Manager、IT-Tools、MyIP，可在应用中心选择安装并调整应用端口。

从固定源码构建，不是拉取原版面板

二开仓库目前没有发布独立 Docker 镜像。NetDeploy 从 GitHub 下载并核对固定源码提交 66aec693a974，用仓库的 docker/Dockerfile.apps 构建本机镜像 netdeploy/dockge-apps:66aec693a974。构建所用的上游 Docker 基础镜像不是不可变 digest；新源码版本需在 NetDeploy 更新后明确审核。

  1. 在 Debian 12/13 或 Ubuntu 22.04/24.04/26.04/26.10 VPS 上选择 Dockge Apps。若是没有 Docker 的干净系统，会自动把 Docker Engine、Buildx、Compose v2 插件及 Git 纳入部署计划；已有可用环境则跳过。全新环境建议至少 4GB 空间，TCP 5001 不得占用。
  2. 打开 项目中心 → Dockge Apps → 部署项目，选 VPS 并查看自动检测生成的计划：Docker/Compose 已就绪时为 4 步，干净 VPS 缺依赖时为 8 步，仅缺官方 Compose 插件时为 7 步。一次审批后自动先装依赖、再构建并启动 Dockge Apps，不用再进 SSH 执行手工命令。
  3. NetDeploy 保持数据目录 /opt/netdeploy/dockge/data，源码保存在 /opt/netdeploy/dockge/source，Compose 文件为 /opt/netdeploy/dockge/compose.yaml。项目栈目录 /opt/stacks 不会被删除或移动。
  4. 安装完成后点击 查看 Dockge Apps 面板信息，复制 SSH 隧道命令。在 Windows PowerShell 运行并保持窗口打开，再访问 http://127.0.0.1:5001/。第一次访问需在 Web 中创建管理员账号。
自动安装 Docker 的安全策略

本功能参考 slobys/docker 的一键安装体验，但不会执行其 curl | bash 远程脚本，也不会安装仅限 x86_64 的旧式 docker-compose 独立程序。NetDeploy 使用 Docker 官方签名 APT 软件源及 docker-compose-plugin，检查签名密钥和安装冲突；已有旧容器、未知版本或残留目录时禁止自动覆盖。

安装 Docker 可能更改宿主机 iptables / 网络转发规则，部分 Docker 容器端口可能绕过 UFW。务必事先备份、审核计划及云防火墙设置。APT 或网络失败可能留下部分软件包，需要先检查真实 VPS 状态再重试。

# SSH 隧道示例：实际地址与端口请使用面板提供的命令
ssh -N -p 22 -L 5001:127.0.0.1:5001 root@YOUR_VPS_IP
已有原版 Dockge 不会自动升级或迁移

已安装的 louislam/dockge、手动安装的 Dockge Apps 或不完整目录都会触发保护，停止新安装，避免覆盖账号、Stack 和容器数据。如要迁移，请先备份并单独处理，不要用强制重装替代迁移。

Dockge Apps 挂载 Docker Socket，拥有较高服务器权限。NetDeploy 继续强制管理页面只监听 VPS 本机 127.0.0.1:5001，默认禁用内置控制台，不自动开放公网管理端口。安装应用时仍需检查相应端口与现有容器是否冲突。

失败、重试与日志

任务列表将显示等待审批、执行中、已完成、部分成功或失败状态。出现异常时，先查看最后一步实际日志，再通过服务器控制台核对远端程序状态。不同版本固定脚本变更后应刷新旧审批方案，不能继续执行过期计划。
