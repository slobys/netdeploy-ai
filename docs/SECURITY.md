# NetDeploy AI 安全边界和操作规范

**此 Alpha 只适合可信单管理员的实验室或私人 VPS，暂不适合作为可直接公开访问的 SaaS。**

1. **严格 SSH 主机指纹**：首次通过 Paramiko SSH 握手看到的指纹属于未经认证的观察值；必须在云厂商独立控制台执行 `ssh-keygen -lf /etc/ssh/ssh_host_<对应类型>_key.pub -E sha256` 核对。支持 Ed25519、ECDSA、RSA 主机密钥。已固定的密钥不可在 UI 覆盖。
2. **SSH 认证**：密码模式经 Paramiko 密码认证；默认保存在单进程内存中，Windows 可由用户选择保存到原生系统凭据库，重启后可恢复；绝不写入 NetDeploy 数据库、浏览器持久存储、.env 或日志。密钥模式使用单独创建的专用密钥，通过只读挂载提供给 API 进程；两种模式都拒绝自动信任未知主机。密码认证必须通过可信本地访问或 HTTPS 传输，不得直接开放公共 HTTP。每个服务应使用范围最小的访问权限；Alpha 的安装操作必须 root，属于已知高风险限制。
3. **白名单命令**：安装脚本来自版本控制中的 `app/catalog.py`。执行前读取并重建当前模板，拒绝数据库中被篡改的任意脚本；SKILL、日志、用户输入和模型回复都不是可执行命令源。
4. **审批门禁**：计划与真实命令展示、手动输入确认语句、审批前再次预检、计划有效期 10 分钟、同 VPS 单任务互斥，默认没有后台自动更新。
5. **隔离 AI**：Codex 仅运行在另一个可选容器，没有安装 SSH 客户端、SSH 私钥、数据库卷、Docker socket、管理员 API token；只接受脱敏日志。模型产生的建议必须由人判断，不可直接执行。
6. **管理面暴露**：Docker Compose 默认只暴露 `127.0.0.1:8787`。从其他 PC 访问应使用 SSH 本地转发或带 HTTPS、认证、限流和可信访问策略的反向代理。不要直接对公网开放 HTTP。
7. **资源和攻击面**：容器默认非 root，drop all capabilities，read-only rootfs，禁止提权；保留基础 API access token 验证。Windows 上用户明确选择时可由操作系统安全保管 SSH 密码，容器/NAS 不进行明文持久化。
8. **上游供应链**：sing-box 的 APT 公钥通过官方 HTTPS 获取，但尚未锁定指纹；wg-easy 使用 v15 主版本标签而非不可变 digest。正式版需固定来源版本、核验 digest/签名，添加升级审批和回退计划。
9. **结果校验**：远程 shell 返回 0 并不保证服务可用；必须针对各项目补充端口、systemd、TLS 和客户端连通性验收。当前系统只宣告执行结果。
10. **失败处理**：目前没有自动回滚；超时或服务重启后远端可能存在半安装状态。UI 提示 `interrupted` 时不得盲目重试，必须先人工核对。应保留 VPS 快照作为第一阶段真实安装测试的前提。


## 3X-UI v0.2.0 安全策略

3X-UI 仅在通过环境检测的 Ubuntu/Debian root VPS 上开放。官方固定 v3.11.0 安装器的下载内容必须符合源码中 SHA-256，并对无需 TLS 的非交互分支实施严格限定的 localhost 绑定修改；上游二进制通过官方 .sha256 sidecar 校验，但尚未具有独立供应链签名验证。

上游安装器可能输出账号、密码与 API Token，因此所有原始安装 stdout/stderr 仅进入 root 可读取的临时文件，在完成后清除；NetDeploy 只记录无敏感值的步骤结果。管理员凭据需要用户明确请求、通过管理员授权且禁止缓存后，从 VPS 受保护的安装结果文件中临时读取；不写入 NetDeploy 数据库、日志或 AI。

默认 HTTP 管理面板只能经 SSH 隧道访问本机监听地址；检测到公网绑定时停止服务。没有自动回滚或安全自动重试，失败后需人工核实并使用 VPS 快照恢复。

## v0.3.0 HTTPS 直接访问与密码保存的限制

- **Windows Credential Locker**：仅接受原生 Windows keyring 后端，关闭或不可用时拒绝明文回退。凭据按本机数据目录隔离、受 Windows 用户权限约束。管理员令牌不代表授权暴露 Windows root 密码；NetDeploy API 也不会返回 VPS SSH 密码。
- **自动只读检测**：创建部署计划时读取 VPS 最新 OS/arch/root/空间/服务状态，审批前仍按固定安全条件二次检查。任何 root、系统或已有安装冲突变化继续拒绝部署。
- **新装与现有 3X-UI HTTPS**：由两个不同的固定工作流执行，现有面板升级仅签发 TLS、不重跑安装器。根据经验证的 SSH 地址区分公网 IPv4 与域名。TLS 安装要求公网 TCP 80 可达，域名 DNS A 正确、签发程序支持 IP shortlived 配置及续期。
- **不可自动降级**：新安装先以 localhost HTTP 完成，证书未签发/续期未配置则停止于本地；升级现有面板也只在最终证书验证成功后修改监听。任何启动或验证失败会尝试恢复 localhost；没有独立事务式回滚。IP 证书有效期 160 小时，持续续期不可省略。
- **公网访问风险**：HTTPS 面板是高权限服务；只有管理员明确审批才会启用公网上监听，云防火墙是否开放由管理员自行控制。必须使用强口令、2FA、限制来源 IP。NetDeploy 自己的管理 API 仍不可直接映射公网。
- **凭据操作**：在已经完成部署的任务中按需通过已认证 SSH 验证远端 TLS 与服务状态；单独复制地址、用户名或密码到操作系统剪贴板可能被其他本地程序读取，使用后清理剪贴板。不把凭据发给 AI、日志或源码库。

## v0.3.1 本机免登录和删除任务的安全边界

- 本机免登录 **必须显式** `NETDEPLOY_LOCAL_AUTO_LOGIN=1`。仅 Windows 启动器设置此环境变量并把 Uvicorn 固定到 `127.0.0.1:8787`。其他平台默认关闭。自动取令牌接口同时限制远端 TCP 客户端地址、HTTP Host、Origin、Sec-Fetch-Site 与自定义请求头；跨站和局域网请求拒绝。
- 此模式相当于**信任当前 Windows 登录用户**，不应经公网端口映射、反向代理、容器映射或局域网共享暴露。它无法阻止同一电脑内的恶意程序直接访问本机服务，因此不能用于公共电脑。请锁定 Windows 账户并及时更新浏览器和系统。
- 管理员令牌由启动脚本生成并保存在本机 Git 忽略的 `.env`，不放入 URL、浏览器重定向或启动日志。Web 页仅在本机同源获得令牌；普通 API 仍依赖原有 `X-Admin-Token` 认证。
- 删除部署任务必须带独立明确确认；服务端事务拒绝删除仍在运行/排队的任务以及有 HTTPS 依赖关系的安装源任务。**仅删除 SQLite 任务历史**，不执行远程命令、不操作服务器、不会删除已保存的 SSH 主机指纹和凭据。删除后失去该任务的日志及访问入口，须提示用户先备份。
- SSH 不同故障用不同提示，特别是主机密钥变化会阻断连接且不能自动替换 `known_hosts`。不要将“已安全保存密码”当成“SSH 指纹或网络验证成功”。


## v0.3.2 Certbot 诊断的安全性

- 新安装通过已验证 SSH 服务器地址自动选择公网 IPv4/域名证书，生成确定性的白名单脚本；用户不能通过任意输入注入 shell 脚本或选择不可信证书源。
- Certbot 的原始标准输出/错误输出可能包含 ACME 验证令牌、URL 及证书元信息；只写到 VPS root 私有的临时日志，并在脚本结束时清理。NetDeploy 任务日志不显示原文，只显示预定义错误类别与修复指导。Certbot 自身的系统日志仍由 Certbot 保管，不会经 AI 上报。
- 新旧部署均在签发、证书链/身份、续期服务检查通过之前不开放公网管理端口；失败时不能改为向公网暴露 HTTP。HTTPS 已安装的 VPS 再次点击部署只创建独立的升级计划；平台绝不自动重新运行原 3X-UI 安装器。
- 公网 HTTP-01 的 TCP 80 必须能从 Let’s Encrypt 验证节点访问；本地 `ss` 检查没有能力保证云安全组和公网路由放行。只有用户核查网络条件后明确批准，才会触发下一次 CA 请求，防止速率限制。

## v0.3.3 SSH 主机重装与设备删除边界

- `data/known_hosts` 是按 **SSH 地址+端口** 共用的信任数据库，与服务器显示名称或 UI ID 无关。多个条目引用同一 IP/端口时，不能为其中一个条目单独信任与其他条目不同的 SSH 公钥。
- 用户必须独立核对 VPS 云控制台中 `ssh-keygen -lf /etc/ssh/ssh_host_<算法>_key.pub -E sha256` 的输出，然后在界面确认新指纹及输入与服务器地址一致的 `REKEY <hostname>:<port>` 语句。后端重新进行未经认证的 SSH 握手，严格比对新指纹及先前已固定的旧指纹，任何不符或模糊的 known_hosts 格式都拒绝自动覆盖。
- 更新信任时只定向替换该地址/端口对应的条目，保留其他主机密钥，生成仅本机可读取的 `known_hosts.backup-*` 备份。更改前会使所有共享该 IP/端口的旧预检和待批准计划失效，并递增 trust_epoch；旧完成任务保留日志但因不匹配 epoch 不能读取新服务器上的登录凭据。
- 同地址有执行中/排队任务时禁止 rekey；本地删除 VPS 时如有任务必须明确选择连同历史记录一起删除；不能远程卸载，也不会静默清除其他 VPS 或共享指纹。
- UI 中的“已保存 SSH 密码”只表示本机可取回凭据，并不代表信任的主机密钥或账号仍属于重装后的系统。重新信任后应人工检查该 VPS 的 SSH 密码是否改变；新系统上的高权限操作仍需要计划和审批。

## v0.3.4 按端口放行与一次批准的安全约束

- 只提供 **UFW 指定端口 TCP/UDP 放行**，参数由严格整数与协议枚举生成固定 SSH 脚本。需要已验证 SSH 主机密钥及管理员授权；没有全局关闭 UFW、清空规则或隐式开放所有端口的功能。
- 新的 3X-UI HTTPS 流程先处理本机 UFW 的 TCP 80，确保 HTTP-01 可使用；通过可信证书链、IP/域名匹配、续期任务与本机 HTTPS 验收后才处理管理端口。执行中失败时保留或尝试恢复原 localhost 安全模式，绝不回退为公网明文管理面板。
- **云厂商安全组独立存在**：NetDeploy 没有供应商授权，不可能通过 UFW 操作替代云安全组。本机开通成功后，仍需确认云平台入站允许 TCP 80 及 HTTPS 管理端口。
- APT 采用 `DPkg::Lock::Timeout=240` 等待无人值守更新，不允许删除锁文件、杀死 `unattended-upgrades` 或为了部署直接禁用安全更新。
- “一次点击批准”只替代反复人工输入确认语句。管理员 Token、已经核对的主机密钥、任务 10 分钟有效期、固定受审脚本校验、审批前二次预检都保留。不能自动运行 AI 生成的远程 shell。

## v0.3.5 简化审批导航仍保留安全检查

- 当 SSH 当前公钥与已固定记录完全一致时，显示“验证通过”，不要求再次提交信任；但首次连接或主机密钥变化必须按原有云控制台独立核对与二次确认规则执行，不提供跳过按钮。
- VPS 待审批任务在概览顶部展示的“继续审批”只是打开原有固定部署任务详情，不直接发出任何远程命令；只有管理员主动点击详情中的“确认并一键部署”才调用审批 API。仍执行 SSH 身份校验、超时检查和系统二次预检。
- 过期计划主动提示重建；界面避免重复创建有效任务，但后台仍按计划有效期校验，不依赖浏览器时钟确保安全。
- UI 的 Node 仿真测试验证状态和内容组织，不构成真实浏览器布局或无障碍全面验收。

## v0.3.6 已有 3X-UI 只读访问的边界

- 已安装检测经已验证 SSH 主机密钥与管理员鉴权，先识别 x-ui 服务与 root-owned 0600 安装文件，不输出安装账号、密码或 API Token 到任务和状态接口。
- 只有用户主动打开已有面板信息时才允许访问敏感凭据；原始文件只可能反映安装时状态，不覆盖或重置后来更新的密码、端口或 Web 路径。
- 仅在可信 TLS 证书验证当前公网 IP/域名成功时提供 HTTPS 直达地址；若证书不可信或服务监听不明确则拒绝外部直连，不会自动回退公网 HTTP。
- 对于未知安装源、缺失凭据文件或未运行服务，不假定默认管理员账号，也不能因为旧任务丢失而自动重装。HTTPS 恢复须核实真实 root-only 安装文件、端口及 localhost 监听，后续仍由固定脚本和明确批准执行。
- 后端 `POST /api/jobs` 对已存在 x-ui 的新装请求直接返回 409；不能制造“零执行步骤却等待审批”的新任务。

## 上线前必须补齐

- 多因素认证、RBAC、多租户数据隔离、审计不可变存储
- 使用按命令限制的 sudo helper / 独立远程 Agent 取代 root SSH
- 可信构建清单、固定版本/digest、签名和透明的升级策略
- 真正可验证的事务式回滚/快照、幂等重试、超时后远端任务判定
- TLS 域名、反向代理限制、CSP 响应头、CSRF/CORS 严格策略和更强速率限制
- 沙箱安全评估、供应链与渗透测试

## 已知限制

SSH 预检、安装等真实操作会访问目标设备；在用户没有提供真实 VPS 与确认之前，没有测试或修改任何实际服务器。安全和有效性只能在隔离测试机验收后再扩大开放。
