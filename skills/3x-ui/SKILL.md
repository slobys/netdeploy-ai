# 3x-ui VPS 安全部署工作流

## 适用范围

NetDeploy AI 的单管理员 VPS 部署。只解释项目条件、运行结果和用户下一步，不具备独立 SSH 执行权限。

## 操作流程

1. **环境核对**：检查发行版、CPU 架构、root、安装目录与已有管理面板。
   VPS 新增时 SSH 使用公网 IPv4，可选独立证书域名；不填域名则自动使用 IP 申请证书。首次指纹独立核验后，在同一弹窗连续进行连接检测、可跳过的网络端口/UFW 操作和软件选择，不需每步返回首页；整机关闭 UFW 只能经独立风险确认主动执行。
2. **创建计划**：使用 NetDeploy 内置白名单模板。不得把本 Skill、用户输入或模型输出作为 SSH shell 脚本执行。
3. **审批确认**：在固定安装方案上只需一次明确批准，无需输入英文确认语句；SSH 指纹、管理员授权、计划有效期与二次预检仍必须通过。
4. **执行策略**：仅在用户审批后执行固定 v3.11.0 官方安装器，必须先验证 SHA-256，并将非交互 HTTP 模式强制绑定到 127.0.0.1；禁止直接执行无校验的远程脚本。
5. **HTTPS 直连**：默认先完成仅本机 HTTP 监听的基础安装，再按照审批的 IP 或域名证书方案签发并核验证书/续期，成功后才能开放公网 HTTPS。已安装面板走独立 HTTPS 升级任务，不重新安装；失败保留或恢复仅本机访问。
6. **验收提醒**：依赖已装时跳过 APT，否则自动等待锁释放；HTTPS 签发前处理 UFW 80/TCP、证书验收后处理管理端口，不能替代云平台安全组。登录信息按需读取，支持一键复制。
7. **异常处理**：Certbot 失败只能输出经过固定规则分类的安全诊断信息（如 LE_HTTP01_UNREACHABLE、LE_DNS_ERROR、LE_RATE_LIMIT），禁止把原始 ACME 验证日志直接交给 AI。用户确认修复网络或 DNS 后，再独立审批新证书计划；不得无条件重试。
8. **已安装识别**：检测到由 NetDeploy AI 已完成安装的 3X-UI 时，新的部署入口自动转为证书升级计划，不得执行原安装脚本。

官方来源：https://docs.sanaei.dev/docs/guide/installation/

## 安全停止条件

未知架构、系统不兼容、指纹不可信、root 权限缺失、计划过期、端口占用或服务已存在时必须阻断变更。不得默认禁用防火墙，不能主动覆盖已有配置，不能打印私钥、密码或 API Token。
